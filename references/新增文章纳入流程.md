# 新增一篇文章 · 纳入流程（权威操作手册）

> **这是「纳入新文章」的唯一权威手册。动新文章之前，先从头读完本文。**
>
> 本文取代 `SKILL.md` 的 6 步流程与 `README.md` 的「添加一篇新文章」小节——
> 那两处是早期版本，**漏了元数据步骤、且示例数据文件已过期**（详见 §1 与 §8）。

---

## 0. 三条铁律（违反任何一条都会造成不可逆损失）

| # | 铁律 | 为什么 |
|---|---|---|
| 1 | **`articleId` = 文章 HTML 文件名（含 `.html`）**，发布后**永不改名** | 所有按篇 localStorage key（`annotations:` / `summary:` / `translation:` / `settings:` / `syntax:` / `reading:` / `wsj_reader:crossref:` / `wsj_reader:article:`）都以它为后缀。改文件名 = 该篇笔记、生词、翻译修改、阅读进度**全部失联** |
| 2 | **`slug`（栏目 ID）的唯一来源是 `<body data-edition="...">`** | 项目历史上散落过 **5 处**「文件名→slug」映射表（已清理 2 处另加 4 处硬编码 EXAM_SLUGS）。**不要新建任何映射表**，一律读属性 |
| 3 | **源码在 `src/`，产物在 `articles/`** | 改完 `src/js/*.js` 必须 `concat` + `sync` 才会生效，否则是经典「改了没生效」 |

## 1. 前置条件：`_articles.json`

`build_html.py` 的数据源。**它被 `.gitignore` 忽略，仓库里没有，需要你本地自建。**

schema 详见 `references/data-schema.md`。**必需字段**（缺任一 → `KeyError`）：

```json
[
  {
    "html": "SundayTimes_2026-06-14_XXX_Author_EN-CN_final.html",
    "en_title": "...", "cn_title": "...",
    "en_author": "By ...", "cn_author": "作者：...",
    "en_sub": "", "cn_sub": "",
    "thesis": ["主旨句1", "主旨句2", "主旨句3"],
    "para_summaries": [["EN 摘要", "CN 摘要"], ...],
    "en_body": "<blockquote>...</blockquote><p id=\"para-1\" data-para-idx=\"1\">...</p>...",
    "cn_body": "<p id=\"para-1\" data-para-idx=\"1\" class=\"cn-translatable\">...</p>..."
  }
]
```

> ⚠️ **`examples/_articles.sample.json` 是过期 schema**（字段是 `id` / `title` / `paras`），
> 直接 `cp examples/_articles.sample.json _articles.json` 会立刻报
> `KeyError: 'html'`。**不要照 README「快速开始」那段做**，按上面的字段表手写。

产出文件名格式（现有 9 篇的惯例）：
`<刊名>_<YYYY-MM-DD>_<主题>_<作者>_EN-CN_final.html`，写在 `articles/` 下。

## 2. 纳入流程（7 步）

### Step 1 · 提取英文段落

```bash
python scripts/extract_paragraphs.py --input article_en.md --lang en --format html > en_body.html
```

规则（**最易出错**，详见 `SKILL.md` Failure mode #1）：
- 段落必须 `<p id="para-N" data-para-idx="N">`，**`id` 与 `data-para-idx` 必须一致**
- 段号从 1 连续到 N，中间不许跳号
- 引言用 `<blockquote>` 包，**不要**用 `<p>`
- 最后一段通常是 bio 段（"Mr./Ms. … is a professor of …"），**必须保留**（`gen_summaries.py` 会自行跳过）

### Step 2 · 提取中文段落

```bash
python scripts/extract_paragraphs.py --input article_cn.md --lang cn --format html > cn_body.html
```

- 与 EN **段数严格相等**，`id` / `data-para-idx` 与 EN 一一对应
- 每段加 `class="cn-translatable"`（前端靠它做 contenteditable）
- bio 段也要翻译

### Step 3 · 校验 EN/CN 对齐

```bash
python scripts/verify_alignment.py --data _articles.json
```

**不通过就停下来**——是合并段、删段还是补段，找用户确认，不要靠「忽略差异」绕过。

### Step 4 · 生成段摘要 + thesis

```bash
python scripts/gen_summaries.py --data _articles.json --thesis-file thesis.txt
```

- `thesis` **必须手写** 3 句中文主旨（AI 自动提取常常失真），生成后把 `【待填】` 替换掉
- bio 段不进 `para_summaries`

### Step 5 · 登记栏目 ID（新增栏目时才有这一步）

在 **2 处** 同步登记 `EDITION_KEYS`（都是 `(正文文件名关键字, slug)` 二元组列表）：

| 文件 | 位置 | 作用 |
|---|---|---|
| `scripts/build_html.py` | `EDITION_KEYS`（约 161 行） | 构建时推导 `data-edition` |
| `scripts/sync_article_meta.py` | `EDITION_KEYS`（约 24 行） | 回写产物 `data-edition` |

可选装饰：`build_html.py` 的 `ARTWORK_SVG` / `ARTWORK_CAP` 加一条编辑部线稿插画（不加则无插画，不影响功能）。

> 注意：这仍然是 2 份同类映射。是历史遗留，**未合并**（见 §8）。加新栏目时**不要只改一处**。

### Step 6 · 构建 + 同步

```bash
python scripts/concat_reader.py                              # src/js/*.js -> src/reader.js
python scripts/build_html.py --data _articles.json --out-dir articles/
```

`build_html.py` 会顺带做这些事（**不需手动**）：
- 把 `src/reader.css`、`src/reader.js` 写进 `articles/`
- 把 `src/js/06-exam.js` 拷贝为 `articles/exam-panel.js`（懒加载的独立文件）
- 从 `scripts/WSJ_Hub_template.html`、`scripts/WSJ_Compare_template.html` 生成 `articles/WSJ_Hub.html`、`articles/WSJ_Compare.html`
- 按 `edition_of()` 推导并写入 `<body data-edition="...">`，按「同目录是否存在 `exam_<slug>.html`」推导 `data-has-exam` / `data-exam-types`

### Step 7 · 收尾

```bash
python scripts/sync_article_meta.py     # 回写/校正 <body> 元数据（幂等）
python scripts/stamp_assets.py          # 刷新 ?v= 缓存戳（按 mtime，幂等）
```

新文章若无考试，`sync_article_meta.py` 会正确地**不写** `data-has-exam`——工具栏的考试入口自动隐藏，无需改任何 JS。

## 3. `<body>` 元数据契约（**这是唯一真相来源**）

成品文章 HTML 的 `<body>` 形如：

```html
<body data-edition="ai_cost" data-has-exam="true"
      data-exam-types="reading,cloze,newtype,translation">
```

| 属性 | 取值 | 谁来读 | 缺失时行为 |
|---|---|---|---|
| `data-edition` | slug，如 `ai_cost` | `00-head.js` 的 `articleMeta.slug`；`reader.css` 的栏目配色 | slug 为空 → 考试入口不显示 |
| `data-has-exam` | `"true"` 或不写 | `articleMeta.hasExam`，控制工具栏「考试」菜单显隐 | 视为无考试 |
| `data-exam-types` | 逗号分隔题型 | `articleMeta.examTypes` | 回退默认 4 类 |

读取优先级：**属性优先，文件名兜底**（`exam.js` 早已如此实现，`reader.js` 已对齐）。
因此**复制一篇文章并改文件名后，考试入口照常工作**。

`articleId` 仍然是文件名——这是刻意的：Hub、WSJ_Compare、文件系统扫描、`navigateToRef` 全部把 `id` 当文件名用。

## 4. 考试 / 练习页（可选）

考试模式 = **5 个相互独立的模块**：`reading` 阅读理解 / `cloze` 完形填空 / `newtype` 新题型 /
`translation` 翻译练习 / `writing` 写作。

- **「有哪些模块」的唯一事实来源是 `<body data-exam-types>`**，由 `scripts/sync_article_meta.py`
  从 `EXAM_TYPES` 常量写入。reader.js 的「考试」菜单与「考试模式总览」面板都读它动态生成。
- 每类怎么进，由 `src/js/10-toolbar.js` 的 `EXAM_MODULES` 注册表描述（`prefix` 拼页面名，或 `panel` 开面板）。
- **新增一类考试模块 = 改两处**：`sync_article_meta.py` 的 `EXAM_TYPES` + `10-toolbar.js` 的 `EXAM_MODULES`。
  菜单与总览会自动出现该模块，不需要再改文章 HTML。

```bash
python scripts/build_exam.py
```

> ⚠️ **`build_exam.py` 不接受任何命令行参数。** README 里写的
> `--question ... --out ...` 会被**静默忽略**。它的行为是遍历脚本内硬编码的
> `SLUG_TO_ARTICLE` 映射，**重建全部 9 个考试页**。

新增文章要出考试页，必须：
1. 在 `scripts/build_exam.py` 的 `SLUG_TO_ARTICLE` 加一行 `'<slug>': '<文章HTML文件名>'`
   ——这是第 3 份同类映射（见 §8）
2. 在 `questions/<slug>/` 放 `mode*.md` 题目文件（出题规范见 `questions/_PROMPT_TEMPLATE.md`）
3. 跑 `python scripts/build_exam.py`
4. 再跑一次 `python scripts/sync_article_meta.py`（此时 `exam_<slug>.html` 已存在，`data-has-exam` 才会被写上）

完形 / 新题型 / 翻译页（`articles/cloze_*.html` 等）目前是**手工产物**，没有构建脚本。

## 7. 常见坑

| 症状 | 根因 | 处置 |
|---|---|---|
| `KeyError: 'html'` | `_articles.json` 用了 `examples/_articles.sample.json` 的过期 schema | 按 §1 字段表重写 |
| `ERROR: data file not found` | `_articles.json` 不在项目根 | 见 §1 |
| 摘要整体错位 N 段 | 改了 `id="para-N"` 忘了同步 `data-para-idx` | 两个属性永远一起改；改完必跑 `verify_alignment.py` |
| CN 比 EN 多/少一段 | EN 漏了 quote 块，或 CN 漏了 bio 段 | 补段，不许绕过 |
| 改了 JS 但页面没变 | 只改了 `src/`，没 `concat` + `sync`；或浏览器缓存 | 跑 `.\build.ps1 sync`，再跑 `stamp_assets.py` |
| 新文章工具栏没有考试入口 | 没跑 `sync_article_meta.py`，或缺 `exam_<slug>.html` | 先建考试页，再跑 meta 同步 |
| 笔记列表为空 / 统计归零 | 文章 HTML **改名**了 | 改回原名。数据 key 以文件名为后缀，改名即失联 |
| `build.ps1 all` 报错 | 依赖 `_articles.json`，见 §8 | 改用 `concat` + `build` + `meta` + `stamp` |

## 9. 阅读版式与试卷版式（新文章自动获得，无需配置）

| 版式 | 位置 | 新文章要做什么 |
|---|---|---|
| **报纸阅读页**（默认） | 代码 `src/js/10-newspaper.js`，样式在 `src/reader.css` 末段 | **什么都不用做**。它运行时从 `.main-wrap .col-body.en` / `.col-body.cn` **搬真实段落元素**进各版，按测量结果自动分版（页内双栏）。报头栏目名取自 `<body data-edition>`（未登记的 slug 回退通用刊名），出版日期取自 `.title-block .meta` 的第二段 |
| **三栏对照**（备用） | 视图 ▾ → 三栏对照 | 无 |
| **考研试卷版式** | 考试页；代码 `articles/exam.js` 的 `initPaperSkin()`，样式在 `articles/exam.css` 末段 | 无。生成考试页后自动套用 |

**改这两处时必须知道的约束**：

1. 报纸版**搬的是真实元素**（段落 `<p>`、`<blockquote>`），不是克隆内容 —— 目的是让标注 `<mark>`、
   词频 `<span>`、译文 `contenteditable`、阅读位置随元素一起工作。
   因此**每页正文容器必须带 `col-body en` / `col-body cn` 类**，否则 `02-content` / `05-export` /
   `08-search` 那些 `querySelectorAll('.col-body.en p[data-para-idx]')` 的代码会漏掉后面几版。
2. 进入报纸版时，**原列会被清空并摘掉 `col-body` 类**（改成 `np-source`），退出时按原始子节点顺序还原。
   任何时刻 `.col-body.en` 只对应一套真实段落，不要制造两个同名容器。
3. 考试页皮肤通过 `MutationObserver` 跟随 `renderQuestions()` / `renderAnsheet()` 的重建，把题号显示改成 `21…`。
   它**只改显示文本**，`data-qno` / `data-as` / `radio name` 全部保持原值——这是交卷判分与答题卡跳转的依据。
4. 新增/修改 `src/js/*.js` 模块时，`10-newspaper.js` 必须排在 `10-toolbar.js` **之前**。
5. **中文列可以有自己的分段**：报纸版把英文列与中文列**各自独立成流**，
   中文版的段落数不必等于英文版 —— 只要中文列里是「一段完整的译文」，它就会成为中文报纸的一段。
   **不要**在 `paperBuild` 里按 `data-para-idx` 去配对 EN/CN，那会把中文列独有的段落静默丢掉。
6. 报头日期优先从 `.title-block .meta` 里取「带四位年份」的那一段，取不到就回落到**文件名里的
   `YYYY-MM-DD`**（`<来源>_YYYY-MM-DD_<slug>_..._EN-CN_final.html`）。
   ⚠ 目前 9 篇里有 1 篇的 meta 完全没写日期（Science 那篇），所以**文件名里的日期不能省**；
   命名时也必须把 ISO 日期带上，否则报头会显示成「今天」。
7. 报纸版分版有 4 条硬约束（改 `10-newspaper.js` / `reader.css` 前必读）：
   ① `.np-body` 同时带 `col-body` 类，必须显式 `padding: 0` —— 基础样式的 `padding:…80px`
      在多栏容器里不是留白，而是**把每栏高度砍掉 80px**（约占一版 21%）。
   ② 分版前必须清掉段落上的 inline `min-height`（三栏「跨列等高」`doHeightSync` 写的，
      最长可见 600px+）。它在页面载入时先于报纸版执行，不清就会按被撑大的高度分版 →
      段落之间一大片空白、版数近乎翻倍。
   ③ 读 `scrollWidth` 判断溢出之前必须 `void body.offsetWidth` 强制重排，否则
      `removeChild` 之后拿到的是上一次布局的缓存值，回退循环会一路删到只剩一个块。
   ④ 报纸调色板 `--np-*` 必须挂在 `body.paper-open` 上，**不能只挂在 `.paper-root` 上**——
      导读抽屉 / 剪报本 / 批注笔 / 检索浮窗都在 `.paper-root` 之外。同时**不要在 CSS 里
      声明 `--np-font`**，字号由 JS 写到 `<html>` 的内联样式（A+/A− 依赖它）。
8. **新增浮层必须同步抬层级**：`.paper-root` 是 `z-index:9000` 的不透明整屏元素。
   任何挂在 `body` 下、层级低于它的浮层，在**默认的报纸阅读模式下会被整个盖住**（点了没反应、不报错）。
   交互菜单类抬到 9250、面板类抬到 9300 —— 统一写在 `src/reader.css` 末尾的「报纸模式下的浮层层级修复」那一块。
   已经踩过的坑：批注菜单、长难句/素材/写作工坊/阅读统计面板、备份对话框、文章关联、阅读位置书签。
9. 文章页的 `.toolbar` **必须保留**（含 `.toolbar-right > .toolbar-clock-area > #toolbar-clock / #session-timer / #total-timer`）：
   报纸模式会把四个 `.menu-trigger-wrap` 与时钟区搬进报眉，退出时按记录的位置原样搬回。
   改文章模板时若把 `.toolbar-clock-area` 删掉也能工作（会退化为逐个搬三个时钟元素），但**不要把 `.menu-trigger-wrap` 去掉**，
   否则报纸版就没有「视图 / 考试 / 数据 / 工具」入口了。

## 10. 快速通道（只加一篇、不想读全文时）
