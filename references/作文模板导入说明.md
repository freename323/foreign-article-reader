# 作文模板：功能说明与导入指南

> 对应功能：**F05 大作文框架模板**、**F06 小作文应用文模板库**、**F17 作文自评清单**
> 入口：文章页 → 工具栏「考试」→「写作」（或考试模式总览 → 写作）→ 写作工坊 → **🏛 大作文** / **✉ 小作文** / **⬇ 模板导入**

---

## 一、为什么要「导入」而不是内置

代码里只放**骨架**（三段式的槽位、10 类应用文的格式与结构）；
**套话库、开头句式、范文、你自己的框架都靠导入**。这样：

* 换一套模板不用改代码、不用重新构建产物；
* 你手里的机构讲义、自己的总结，粘一段 JSON 就能进来；
* 导入的内容只存在本机 localStorage（键 `wsj_writing:templates`），会进「备份全部数据」。

内置骨架的清单（点「恢复内置骨架」可以随时回到这一版）：

| 类型 | 内置内容 |
|---|---|
| 大作文 | 1 个「三段式通用框架」：第一段图画描述 60-80 词 / 第二段寓意揭示与论证 120-150 词 / 第三段观点与建议 40-60 词。**开头句式为空，等导入** |
| 小作文 | 10 类：建议信 / 投诉信 / 邀请信 / 感谢信 / 道歉信 / 推荐信 / 求职信 / 通知 / 告示 / 备忘录。各带格式与结构，**套话库为空，等导入** |
| 自评清单 | 5 维：内容完整 / 语法准确 / 词汇多样 / 句式多样 / 衔接连贯（可用导入的 `checklist` 覆盖） |

---

## 二、怎么用（三步）

1. **导入**：写作工坊 → 「⬇ 模板导入」→ 把 JSON 粘进文本框（或点「从文件读取…」选 `.json`）→
   点 **「解析并合并」**（推荐；同一个 `id` 会覆盖，不会产生重复条目）或 **「替换全部」**。
2. **写大作文**：切到「🏛 大作文」→ 选框架 → 点「＋ 新建草稿」→ 逐段写；
   段上方的句子按钮点一下即插入；右侧/下方「📎 插入素材」可以从你从文章里存的素材一键搬过来。
3. **写小作文**：切到「✉ 小作文」→ 选应用文类型 → 点「＋ 新建这篇作文」→
   套话按钮（开头 N / 结尾 N）点击插入 → 写完在「作文自评清单」打 1-5 分。

**草稿是自动保存的**（停止输入 0.6 秒后写盘，键 `wsj_writing:essays`），刷新不丢。
草稿下拉可以切历史作文，右边 ✕ 删除，右下角「导出这篇」把全文 + 自评拷成 Markdown（可粘进 Word）。

## 三、导入格式

### 3.1 完整格式（推荐）

```json
{
  "name": "我的考研写作模板",
  "big": [
    {
      "id": "big_ai_jobs",
      "title": "AI 与就业",
      "topic": "科技",
      "note": "图画作文：一张图 + 一句评语",
      "slots": [
        {
          "key": "p1",
          "label": "第一段·图画描述",
          "role": "描述",
          "words": "60-80",
          "tip": "一句总体描述 + 两句细节，注意图上的文字",
          "starters": [
            "As is vividly depicted in the picture, ...",
            "The drawing portrays a scene in which ..."
          ]
        },
        { "key": "p2", "label": "第二段·寓意揭示与论证", "role": "论证", "words": "120-150", "starters": ["The picture implicitly reflects ..."] },
        { "key": "p3", "label": "第三段·观点与建议", "role": "结论", "words": "40-60", "starters": ["From my perspective, ..."] }
      ]
    }
  ],
  "small": [
    {
      "id": "small_suggestion",
      "type": "suggestion",
      "name": "建议信",
      "format": "称呼 + 正文 + 落款",
      "structure": ["写信目的", "具体建议（2-3 条）", "期望回复"],
      "openings": [
        "I am writing to suggest that ...",
        "Regarding ..., I would like to make some suggestions."
      ],
      "closings": [
        "I hope my suggestions will be helpful.",
        "Thank you for your consideration."
      ],
      "samples": [
        { "title": "给图书馆的建议", "text": "Dear Sir or Madam, ..." }
      ]
    }
  ],
  "checklist": [
    { "key": "content",  "label": "内容完整", "hint": "三段齐全、要点无遗漏" },
    { "key": "grammar",  "label": "语法准确", "hint": "时态一致、无残缺句" },
    { "key": "vocab",    "label": "词汇多样", "hint": "避免重复用同一词" },
    { "key": "syntax",   "label": "句式多样", "hint": "至少一个从句" },
    { "key": "cohesion", "label": "衔接连贯", "hint": "段落间有过渡" }
  ]
}
```

### 3.2 字段表

**顶层**

| 字段 | 必填 | 说明 |
|---|---|---|
| `big` | 至少 `big` / `small` 有一个 | 大作文框架数组 |
| `small` | 同上 | 小作文模板数组 |
| `checklist` | 否 | 自评清单；不写就沿用现有的 |
| `name` | 否 | 模板集的名字，只用于显示 |

**`big[]` 每项**

| 字段 | 必填 | 别名（也认） | 说明 |
|---|---|---|---|
| `id` | 建议填 | — | 相同 `id` 合并时覆盖；不填会自动生成 |
| `title` | 建议填 | `name` | 框架名，显示在下拉里 |
| `topic` | 否 | `theme` | 话题标签，只用于显示 |
| `note` | 否 | `desc` | 备注 |
| `slots` | 是 | `framework` / `paragraphs` / `parts` | 段落槽位数组；`paragraphs` 是对象时按 key 排序后转数组 |

**`slots[]` 每项**

| 字段 | 必填 | 别名 | 说明 |
|---|---|---|---|
| `key` | 建议填 | `id` | 槽位标识（草稿按它存文字）；不填按 `p1/p2/p3…` |
| `label` | 建议填 | `name` / `title` | 显示名 |
| `role` | 否 | `func` | 标签，如「描述 / 论证 / 结论」 |
| `words` | 否 | `wordCount` / `length` | 字数建议，写成 `"60-80"` 这样的字符串 |
| `tip` | 否 | `hint` / `note` | 写作提示 |
| `starters` | 否 | `templates` / `openings` / `phrases` / `sentences` | 开头句式，点一下插入 |

**`small[]` 每项**

| 字段 | 必填 | 别名 | 说明 |
|---|---|---|---|
| `id` | 建议填 | — | 同上 |
| `type` | 否 | — | 类型标识，不填默认用 `id` |
| `name` | 是 | `title` | 显示名（建议信 / 投诉信…） |
| `format` | 否 | `layout` | 格式说明 |
| `structure` | 否 | `outline` | 结构要点数组 |
| `openings` / `closings` | 否 | `opening` / `closing` | 套话库，点一下插入正文 |
| `samples` | 否 | `examples` | 范文；可以写 `["范文全文"]` 或 `[{ "title": "…", "text": "…" }]` |

### 3.3 三种容错写法

导入器是**故意宽松**的（从别处拷来的 JSON 命名五花八门）：

1. **顶层直接是数组** —— 会自动按特征分流：带 `openings` / `closings` / `format` 的进小作文，带 `slots` / `paragraphs` 的进大作文：
   ```json
   [
     { "name": "感谢信", "openings": ["I am writing to express my gratitude"], "closings": ["Thanks again."] },
     { "title": "图表作文框架", "slots": [{ "label": "第一段" }, { "label": "第二段" }] }
   ]
   ```
2. **只写一部分** —— 只写 `big` 就只更新大作文，`small` 保持原样。
3. **字段用别名** —— 见上面的表；`framework` = `slots`、`templates` = `starters`、`outline` = `structure` 等。

### 3.4 校验与报错

| 情况 | 表现 |
|---|---|
| 不是合法 JSON | 红字「JSON 解析失败：…」，**不会**写坏已有的模板库 |
| 顶层既不是对象也不是数组 | 红字「顶层必须是对象或数组」 |
| 没有 `big` / `small`，也不是模板数组 | 红字「没找到 big / small 数组（也接受顶层直接是模板数组）」 |
| 小作文没有套话 | 导入成功，但提示「小作文「X」没有开头/结尾套话，只导入到结构」 |
| 大作文没有开头句式 | 导入成功，但提示「大作文「X」各段没有开头句式，只导入到槽位」 |

## 四、几条设计约束（改代码前先看）

1. **键名前缀**：新建 localStorage 键一律加 `wsj_` 前缀（`wsj_writing:templates` / `wsj_writing:essays`），
   不要另起 `writing:` 命名空间 —— 项目里已经有两套并存的先例，会分裂数据。
2. **必须在备份白名单里**：`src/js/09-reading.js` 的 `BACKUP_EXACT_KEYS` 要同时含
   `wsj_writing:templates`、`wsj_writing:essays`、`wsj_writing:notes`，
   否则备份会**静默**漏数据（不报错，只是恢复后模板和草稿全没了）。
3. **新增页签要同时挂三处**：`openWritingWorkshop()` 里的 tab 按钮、
   `renderWorkshopBody(tab)` 里的分支、`renderWorkshopOverview()` 的总览卡片。
   （`all` 页签曾经因为缺分支而是一片空白 —— 这是默认页签，等于工坊一打开就是白板。）
4. **浮层层级**：写作工坊是 `.syntax-panel`，报纸模式下的层级已由 `reader.css` 末尾统一抬到 9300，
   新面板只要用这个基类就够了，不用单独写 z-index。
5. **改完必须跑回归**：
