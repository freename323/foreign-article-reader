# F10 完形填空自动生成 —— 质量审查报告

> 审查对象：`articles/cloze.js`（9 篇 `cloze_*.html` 共用的生成器，**不在 git 里**，仅存在于 `articles/`）
> 审查方式：**跑真实代码取样**，不是读代码猜结论 —— `.workbuddy/review_cloze.js` 把 `cloze.js`
> 内联进 9 篇文章页、在 IIFE 收尾前注入一行调试导出，从而拿到全部 180 个空的结构化数据。
> 日期：2026-09-24 ｜ 结论：**6 类真缺陷，全部已修复**，新增 107 项回归断言全绿。

**一句话结论**：选项去重、答案唯一性、判分逻辑这些「不变量」本来就是对的；
真正的问题是**干扰项的质量**——生成器会拿专有名词、不同词形的词当选项，
于是 1/4 以上的空在语法层面就能排除，属于送分题；解析还在给编造的「考研真题 30%」。

## 二、六个真缺陷的成因与修法

### ① 专名污染：词池把 `Buffett` 存成 `buffett`

**成因**：建词池时写的是 `pool[pos].push(lower(w))` —— 大小写信息在入池时就被丢掉了，
而 `posOf()` 恰好把「首字母大写」也当成名词特征（`/^[A-Z]/.test(word) → 'noun'`），
于是 `Buffett / January / Obama / Shropshire` 全部混进了名词池，再被小写输出成选项：

```
pothole#11  答案 drivers  选项 [january, buckinghamshire, handlers, drivers]
fcc_sports#12 答案 nation  选项 [nation, carr, fcc, obama]
```

**修法**：新增 `properWords()` —— 收集「在文中**只以大写形式出现过**」的词
（大小写两种形式都出现过的词不算专名，避免误杀句首实词），再加全大写缩写（`FCC`/`LBJ`）；
词池与干扰项全部过一遍这张表。同时把 `isGapWord` 收紧成 `/^[a-z]{3,}$/`，
一次性排除 `anthropic's` / `low-level` / `deepseek-r` 这类撇号连字符碎片。

> 副作用修正：`Indeed` / `Moreover` 这类**总在句首**因而从不小写出现的连接词会被误判成专名，
> 于是从专名表里显式剔除它们 —— 否则「逻辑衔接题」的选项池会缺掉最常见的几个词。

### ② 词形错配：语法上就能排除的干扰项

**成因**：干扰项只要「词性标签相同」就放行，完全不看形态。实测样例：

```
ai_cost#14   答案 raised(-ed)     选项 [rise, pops, raised, arise]
ammo_shortage#12 答案 take(原形)   选项 [use, reinforced, take, produced]
potholes#2   答案 ...            选项 [submitted, needed, agreed, killed]  ← 现在是对的
```

空处需要过去式，选项给原形 —— 考生不读句子也能排除三项，题目失效。

**修法**：新增 `formOf(w)`（base / -s / -ed / -ing），干扰项必须与答案**词形一致**；
`-ed` 与 `-ing` 互不通用，单复数也不通用。这一条单独把 69 处压到 0。

### ③ 连续挖空：`usedIdx.add(tIdx ± 1)` 屏蔽的是空格

**成因**：token 序列把空白也当独立 token（`'take',' ','into',' ','account'`），
所以 `tIdx ± 1` 屏蔽掉的是**空格**，不是相邻的词，两个实词照样可以连着挖。

**修法**：改成显式间距约束 —— 新空与任一已有空的 token 距离必须 ≥ `MIN_GAP_TOKENS`（8）。

### ④ 段落首句被挖：一个正则写错，禁挖区形同虚设

这里有一个**连锁的隐藏 bug**：我最初用来求「段落首句终点」的写法是
`p.match(/[^.!?]+[.!?]+(\s+|$)/g)[0]` —— 遇到 `the U.S. Senate` 这种缩写时，
正则要求标点后紧跟空白，`U.` 不满足，于是引擎**从 `S. ` 才开始匹配**，
`matches[0]` 变成 `"S. "`（长度 3）。结果「首句」被算成段首 3 个字符，
整段几乎不受禁挖约束 —— 这就是 30/180 的漏网来源。

**修法**：用带 lookahead 的 `/[.!?]["')\]]?(?=\s|$)/` 找**第一个真正的句末标点**，
并用 `end < p.length - 1` 判断「该段是否不止一句」（单句成段不设禁挖，否则整段无空）。

### ⑤⑥ 解析文案：伪权威数字 + 暴露生成机制

原解析每一条都带 `词义理解题（考研真题 30%）`，同一篇里「词义理解」和「近义辨析」都自称 30%，
这些百分比没有任何出处，属于凭空捏造的权威感；`（兜底，…）` 更是直接把「这是补位凑数的题」
写给用户看。

**修法**：解析改为四行固定结构 —— `📌 考点`（题型 + 一句方法）/ `✅ 答案`（带上下文语境）/
`❌ 其他选项`（逐个说明为什么不成立）/ `💡 方法`。
近义辨析与逻辑衔接题会带上**真实的语言学辨析内容**（`SYN_GROUPS` 的组注释、`CONNECTORS` 的逻辑含义），
而不是套模板。数字百分比与「兜底」全部删除。

### ⑧ 隐藏 bug：固定搭配题从未命中过一次

`COLLOCATIONS` 表里有 14 条搭配，但 9 篇实测 **0 个** 固定搭配空。原因：

```js
// 原文 token: ['take', ' ', 'into', ' ', 'account']
c.phrase.every((w, k) => lower(tokens[i + k]) === w)   // tokens[i+1] 是 ' '，永远为 false
```

短语匹配把**空白 token 也算进了下标**，所以任何多词短语都不可能匹配。

**修法**：先建一条「词 token 序列」`wtok = [{t, i}]`，短语在 `wtok` 上连续匹配，
再回头校验这些词在原 token 流里确实连续（中间只能是空白或连字符）。
同时补充了 21 条常见搭配（`in terms of` / `take advantage of` / `give rise to` /
`call into question` / `be subject to` …）并给整篇设 3 个上限，防止一份卷子全是介词。

### ⑦ 答案位置：纯随机时 D 偏多

原来 `orderOpts` 只做 `shuffle(...).slice(0,4)`，9 篇累计下来 D 占 27%、B 占 22%。
180 个样本里这属于随机噪声，但「答案总在 D」一旦被学生察觉就是可利用的规律。

**修法**：按插入序 `gaps.length % 4` 把答案摆到指定位置，四个位置严格各占 1/4（实测 45/45/45/45）。

### 附带修掉：`posOf` 把连接副词判成形容词

`/less$/` 命中 `NOUN_SUF` 之外的 `ADJ_SUF`，于是 `nonetheless` 被判成形容词，
作为干扰项混进实词池。新增 `DISCOURSE` 集合（`however / moreover / nevertheless / meanwhile …`），
`posOf` 对它们返回 `'func'` —— 它们只通过 `CONNECTORS` 库出题，不进实词池。

## 三、残留局限（诚实记录，未修）

| 项 | 现状 | 影响 | 若要继续改 |
|---|---|---|---|
| 词性标签仍不够细 | `posOf` 靠后缀 + 常用词表，`drivers`/`nation`/`traffic` 这类无后缀名词会落进 `pool.word`；当某词性的池不满 3 个时，会退化到 `pool.word` 补位 | 少量空里可能出现「形容词空塞名词选项」（实测 7 处词性标签不一致，其中多数是标签本身的误判而非真的不匹配） | 引入一份词性词表（如 5000 词），或改用小型 POS tagger |
| 语篇衔接题占比波动 | `conn` 2–5 个取决于文章里有几个 `CONNECTORS` 命中 | 一篇文章若连接词少，实词辨析占比会很高（`ai_regulation` 17/20） | 扩充 `CONNECTORS`，或把「代词指代」「介词短语」也做成题型 |
| 近义辨析覆盖面 | 27 组 `SYN_GROUPS`，命中取决于文章刚好出现组内词 | 实测 7 个/180 | 继续按考研真题词表补组 |
| 手工核对的必要性 | 机器无法判断「语义上是否真的只有一个选项说得通」 | 少量空仍可能有两个选项在语境上都勉强成立 | 生成后人工过一遍；本报告末尾附取样脚本 |

## 五、给维护者的两条提醒

1. **`articles/cloze.js` 不在 git 里**（`articles/` 整体被 .gitignore）。
   它没有 `src/` 源码副本、也没有生成脚本 —— 它自己就是唯一真相。
   改它之前必须先手工备份，改完立刻跑 `verify_cloze.js`。
   建议把 `cloze.js` / `newtype.js` / `translation.js` / `exam.js` 纳入版本管理（或至少移进 `src/`）。
2. **新增生成规则时要同时过三张表**：专名表（`properWords`）、词形（`formOf`）、
   间距与首句禁挖（`canPlace`）。任何绕过 `addGap()` 直接 `gaps.push()` 的写法都会重新引入本报告里的缺陷。
