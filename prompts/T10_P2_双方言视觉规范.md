# T10 · P2 · 双方言视觉规范（文档任务，不改行为代码）

> 一句话：仓库里并存"Web 应用语言"和"纸质印刷语言"两套设计方言，已三次引发用户亲历的风格 bug——写一份边界规范文档 + 现有页面清点清单，杜绝第四次。

## 背景（为什么）

历史上三次冲突：① 文库主题与文章主题色值不一致（v37 修复，用户报告）；② 作文文库索引页绿底无衬线 vs 调色版范文纸面衬线（重做对齐）；③ 报纸版折叠剪报本浮压报头（v38 修复）。每次都是"修 bug"而不是"修体系"。项目还有更多页面没爆雷只是因为没被并排看。

理论依据：认知负荷——形态语言不一致增加每次页面切换的重新定向成本；设计系统的价值在边界明确而非风格统一。

## 现状（实码与数据）

两种方言的代表页面：
- **Web 应用语言**：文库 `scripts/WSJ_Hub_template.html`、考试/完形/新题型/翻译练习页、工具栏与下拉菜单、精读分析台、写作工坊面板。
- **纸质印刷语言**：报纸阅读模式（`src/js/10-newspaper.js` + reader.css 的 `body.paper-open` 段，--np-* 变量体系）、调色版作文 HTML（作文包）、作文文库索引（`scripts/sync_essay_html.js` 生成的电子书风）。
- 主题系统：v37 后四套主题色值以 `src/reader.css` 为唯一基准，文库已对齐。

## 任务（做什么）

1. **写 `references/设计规范_双方言.md`**，内容：
   - 两种方言的定义与**适用边界判定规则**（建议：'长文沉浸阅读/成稿展示' → 印刷语言；'管理、练习、数据、工具' → 应用语言；混合场景（如报纸模式里的剪报本）谁从属谁）；
   - 共享层规范：色板（引用 reader.css 四主题的变量名与用途）、字体栈两套（衬线阅读栈 / 无衬线 UI 栈）、间距与圆角尺度、按钮形态两式；
   - z-index 领地协议（9200 报纸层 / 9300 浮层——现状从 reader.css 末尾注释提取，补全为全页面清单）：解决 v31/v34/v38 反复处理的面板叠放问题；
   - 新页面/新面板的方言选型检查单（3 条以内）。
2. **清点清单**（文档附录）：全部页面/面板逐个标注方言归属 + **越界项**（用一种语言做了另一种语言的场景，如工坊面板套在报纸模式里的形态处理是否合规）+ 每项越界给"接受/建议改"结论。范围：9 篇文章页的三栏模式、报纸模式、4 类练习页、文库、作文文库索引、独立写作页、写作工坊、精读分析台、剪报本、浮动菜单。
3. （可选）发现明确的小越界（如某按钮色值硬编码不符色板）列成"建议修复清单"留给后续任务，本任务**不改行为代码**。
