# T08 · P1 · 渲染性能增量化 + 颜色分层开关

> 一句话：renderNotes 全量重建是输入卡顿的第一嫌疑人，同屏四套颜色语言是每读一文都在交的认知税——两个问题一起修。

## 背景（为什么）

① `renderNotes()` 每次调用都 `innerHTML` 全量重建 + 逐节点 `addEventListener`（`src/js/03-notes.js`），搜索框每敲一键就触发（03-notes.js:319-321 的 input → renderNotes）——O(n) 渲染 × 每键。② 同屏叠着四套颜色：5 级词频着色 + 3 色标注高亮 + freq-v 金色 + 锚点，解码"这个颜色是什么意思"本身消耗工作记忆（认知负荷理论）。③ 词频着色是 TreeWalker 全文包装、每词一个 span（07-wordfreq.js:61-105），千词文 = 数千节点替换。

理论依据：认知负荷（视觉解码成本）；Bjork 渐退提示——颜色分层开关同时是 T01 渐退提示的载体（"只看我的标注"= 词频色退场）。

## 现状（实码与数据）

- renderNotes：03-notes.js（全量 innerHTML；页签切换、搜索、删除、renderNotes 调用点分散在 01/02/03/06/07 多个模块）。
- 词频模式键：`wsj_reader:freqmode`（07-wordfreq.js:6，'1' 开 / 其他关——两态）。
- 词频着色：`applyFreqColoring()` + TreeWalker + replaceChild；freq-v 金色在 vocabSet 逻辑（07-wordfreq.js:38 起）。
- 搜索：`setupNotesSearch()`（03-notes.js:310）。

## 任务（做什么）

1. **搜索增量化（最小侵入版）**：搜索 input 不再直接 `renderNotes()`——
   - 300ms 防抖；
   - 防抖后**过滤已渲染 DOM**（按 query 对 `.note-card` 做 display 切换），只有 query 从有→无或页签切换时才全量重渲；
   - `noteSearchQuery` 状态语义不变（其他调用点不受影响）。
2. **事件委托**：notes-list 一级容器挂 click 委托（`data-*` 派发），替代逐卡逐按钮绑定；保留现有 data 属性命名，行为不变。**先盘点 03-notes.js 里所有 per-node 绑定点再动手**（v31 的 `_wsFlush` 闭包陷阱同类：委托后注意闭包引用的是旧 DOM）。
3. **颜色三态开关**：`wsj_reader:freqmode` 升级三态——
   - `all`（默认，全部着色，现状）
   - `mine`（**只看我的标注**：词频五级色全部关闭，只留标注高亮 + freq-v 金/T01 渐退色）
   - `off`（全关，素文）
   - 旧值 '1' 读时映射 `all`（惰性迁移，写时落新值）。视图菜单的词频入口改三态循环或子菜单。
4. **词频着色惰性化（可选 v2，若步骤 1-3 已显著改善可缓做）**：IntersectionObserver 视口内先着色，滚动补着——注意与报纸模式分版（每版有自己的 col-body）和标注 mark 的共存。

## 约束与红线

- renderNotes 的调用点分散在 5+ 个模块，**改动前先 grep 全部调用点**（`renderNotes(`），确认每一处的期望行为（有的调用点依赖全量重渲来清状态——这些保留全量路径）。
- 委托化不得改变现有交互行为（删除/闪烁/跳转/页签切换），回归测试会盯。
- 三态开关与 T04 衔接模式开启时的联动（衔接模式自动降词频色）留接口，T04 自己实现调用。

## 验收（回归断言清单）

- 搜索 300ms 防抖存在；display 过滤路径存在；query 清空时恢复全量渲染路径存在；
- 委托绑定存在（容器级 addEventListener 数量断言：notes-list 区域仅 1 个 click 监听）；
- freqmode 三态：常量/枚举存在、旧值 '1' 的映射逻辑存在、菜单 UI 三态；
- `mine` 态下五级色类不出现（CSS 或渲染条件断言）；
- 手测：一篇 1000+ 词文章开词频着色 → 打开剪报本输入搜索 → 无肉眼卡顿；三态切换各一次视觉正确。
