# T09 · P2 · 学习数据视图（增长曲线 / 错因趋势 / 重逢驱动选文）

> 一句话：把记录型数据升级为决策型——"我比上月强在哪"、"哪类错误在收敛"、"下一篇读什么对词汇最有效"三个问题各给一个视图。

## 背景（为什么）

trace 数据底子极好：每日秒数/词汇/长难句/素材/错题/默写计数（`studyRows()` 聚合）、跨篇词汇重逢计数（`allVocabWords().filter(w => w.n >= 2)`，11-insights.js）、成绩历史（`wsj_exam:history`）、错因枚举（`WRONG_CAUSES`）。但都是计数展示，没有结构分析：无词汇增长曲线（总量 × 掌握度分布）、无错因时间趋势（哪类错误在收敛——数据在 `wsj_exam:wrongs` 等四库 + T02 的强制错因里）、重逢计数只是个数字不驱动任何动作。

理论依据：形成性反馈（Black & Wiliam，效应量 0.4-0.7——反馈的价值在"下一步做什么"）；SDT 胜任感（可感知进步 = 动机燃料）；spaced re-encounter（重逢 = 免费复习）。

## 现状（实码与数据）

- 精读分析台：`src/js/11-insights.js`（KPI 面板 `ins-kpi-item`、错题本视图、能力雷达）。
- 数据源键：`annotations:*`（vocab/qtype/paraFunc）、`reading:*`（每日 session）、`wsj_exam:history/wrongs`、四库 wrongs、`wsj_dictation:stats/wrongs`、T01 后另有 `wsj_vocabrev`。
- 文库文章列表：`scripts/WSJ_Hub_template.html` 的 registry 渲染。

## 任务（做什么）

1. **词汇增长视图**（精读分析台加页签或卡片）：
   - 曲线：按 createdAt 累计的 vocab 标注总量（全库扫描 `annotations:*` 聚合）；
   - 堆叠：当前掌握度分布（T01 后按 vocabrev 的 n/strength 分档：新收录/复习中/渐退中/已沉睡；T01 未做时按标注时间分档）；
   - 一行结论文案（如「累计 412 词，其中 96 词进入复习循环」——结论句比图表重要）。
2. **错因结构趋势**：
   - 按月聚合四库 wrongs 的 `cause` 字段（WRONG_CAUSES 枚举），堆叠面积或分组条形（原生 SVG 或 div 条，不引库）；
   - 高亮"连续两个月上升的错因"——这是下一个训练重点的信号。
3. **重逢驱动选文**（文库侧）：
   - 文库文章卡片加排序按钮「🔁 对词汇最有效」：扫描每篇正文词集（构建时已可提取，或运行时 fetch 文章 HTML 解析）∩ 你的 vocab 池（含 vocabrev），按命中数排序，卡片显示「与你的词汇池重逢 N 词」；
   - 点击 N 展开**重逢词清单**（这正是"下一篇泛读选它"的依据）。

## 约束与红线

- 不引任何图表库——原生 SVG/div，与项目零依赖原则一致。
- 全库扫描 `annotations:*` 是 O(键数 × 条数)，视图打开时算一次并缓存（sessionStorage 或内存缓存，标注变更时失效——复用现有缓存失效模式的思路）。
- 文库运行时 fetch 文章 HTML 在 file:// 协议下可能被 CORS 拦——**先检测协议**，file:// 下降级为"构建时生成词集清单"（scripts/ 里加生成器，构建管线跑）。

## 验收（回归断言清单）

- 三个视图的聚合函数存在（增长累计 / 错因按月 / 重逢交集）；
- 缓存与失效逻辑存在；
- file:// 降级路径存在（协议检测 + 构建时清单）；
- 结论文案生成逻辑存在（不是纯图表）；
- 手测：精读分析台看到三视图；文库按重逢排序后第一篇的 N 与实际标注词吻合（抽查 3 词）。
